# Правила командної роботи 
---

## 1. Робота з Git та гілками

* **Заборона прямих комітів у `master`:** гілка `master` завжди має залишатися стабільною та працездатною.
* **Окрема гілка під кожну задачу:**  Створюйте собі гілки на вашу частину роботу, будь ласка. (`git switch -c назва-гілки`)
* **Синхронізація перед стартом:** перед початком нової задачі оновлюйте локальний `master` (`git pull origin master`) та створюйте нову гілку від нього.
* **Змістовні коміти:** робіть невеликі логічні коміти з чітким описом змін (наприклад, `implement cycle decomposition for permutations`, замість `fix`).

---

## 2. Технічні обмеження


* **Дотримання спільних назв:** представлення дошки, перестановок, ліній виграшу та типів оцінок у кеші є спільними для всіх модулів.
* **Чисті функції без неочікуваних мутацій:** функції переходу станів, застосування перестановок та перевірки ходів не повинні змінювати передані структури даних «на місці».

---

## 3. Тестування та якість коду

* **Тести:** кожен модуль супроводжується юніт-тестами, зокрема на граничні випадки:
* **Читабельність:** використовуйте зрозумілі назви змінних і функцій, типізацію (type hints) та короткі docstrings для ключових функцій.

---

* **Комунікуйте:** якщо задача виявилася складнішою, повідомляйте одразу, щоб вчасно перерозподілити навантаження.
